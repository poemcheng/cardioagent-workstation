# CardioAgent 2.4.0：會診準備中心

將「先定義規格、集中看工具進度、人工調整再交付、以成本資料評估導入」落在既有影像研究工作站。

## 新增功能

- `/workspace`：建立會診準備規格，集中查看待執行、工具受阻、待覆核與已覆核分析。
- 每個規格保存目標、問題、三項人工確認、分析參數、來源檔案與病例資料雜湊。調整時另存新任務，不覆寫原規格。
- 有急性旗標、狀態未知、背景未完整或授權未確認時阻擋一般分析；執行前與執行後核對來源。
- 經影像覆核角色啟動後，執行既有 Python 影像量測、分割／提供標籤、參考比對與 3D 流程；顯示實際階段、來源與時間，連回原分析頁人工覆核。
- 本工作站的文字與音訊模型請求共用有界 FIFO 佇列；記錄等待、執行及失敗，不記錄提示詞，也不宣稱裝置已驗證。
- 成本情境：自行填每月案例數、人工分鐘、含覆核的輔助分鐘、每小時人力成本及每月導入總成本，保存輸入及計算依據。

## 如何操作

1. 本機啟動後開啟 `http://127.0.0.1:8765/workspace`；公開版開啟 `?view=workspace`。
2. 按「新增準備任務」，選擇病例並填入目標與會診問題。可先填入研究範例文字，再依實際情況確認急性狀態、背景及授權。
3. 選擇辨識／分割方式、中心切片及參數，保存規格。未齊資料的規格可保存，但不能執行。
4. 按「執行本次準備」。本機版排入既有單工作者佇列；公開版在訪客分頁的 Python runtime 依序執行。
5. 查看實際工具階段，按「開啟影像與覆核」檢視原圖、遮罩、3D 與來源。人工覆核仍在既有分析頁完成。
6. 原規格需調整時按「另存調整規格」；用「下載規格與結果」保留規格、分析與事件。
7. 成本區自行輸入情境，按「計算並保存情境」。不要把機器處理時間當作含人工覆核的總流程時間。

## 成本計算

單案人力容量價值 =（人工分鐘 − 輔助流程含覆核分鐘）÷ 60 × 每小時人力成本。

每月情境差額 = 單案人力容量價值 × 每月案例數 − 每月導入總成本。

單案價值不大於零時不計算正向損益平衡案例數。此處呈現使用者輸入的假設，不是現金獲利或臨床省時實證；文章中的訂閱價格與軟體報價未套用為本產品成效。

## 實作與邊界

- 沿用 Flask、SQLite、既有分析與人工覆核；新增 preparation_orders、preparation_settings，變更亦寫入既有事件鏈。
- 正式介接 HIS／PACS、跨電腦 agent 調度、牙科口掃／CBCT 配準及治療模擬均未新增。沒有將文章的個人經驗當作本產品驗證。
- 模型閘門只協調本工作站程序發出的模型請求，不管理其他程式或另一台電腦；影像與 Hybrid 的 NPU 共享資源仍須實機驗收。
- 公開版沒有本機 LLM、訓練權重或 AMD NPU；研究 MRI 的 3D 來自提供標籤，不是模型預測。資料只保存在本分頁；本機版保存於資料目錄。
- Windows 軟體 CI 與套件建置不代表 PN54、NPU 或臨床效能已驗證。權重、驅動及 AMD backends 另行準備。

## 驗證紀錄

開發端 217 項 Python 軟體測試通過，包含 13 項新增準備流程與模型佇列測試；7 項準備中心 DOM／實際 Flask transport 檢查，以及既有 7 項 renderer 邏輯檢查通過。DOM 與 renderer 檢查不代表瀏覽器像素驗證。本次瀏覽器控制環境啟動失敗，未完成視覺與公開 WebAssembly 執行驗證。Windows 成績以本版本 GitHub Actions 與 Release 的實際結果為準。
