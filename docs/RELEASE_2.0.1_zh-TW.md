# CardioAgent 2.0.1 修正與執行紀錄

2026-10-31。沿用既有 Flask／SQLite／Lemonade／ONNX 架構與資料格式。版本號以 VERSION.json 為準；外層下載檔沿用原有名稱。

## 本次修正

| 問題 | 修正後行為 |
|---|---|
| 只在前端要求覆核勾選 | 伺服器要求明確的 review_confirmed=true，並再次核對目前版本 |
| 來源變更後仍可核准或帶入舊分析 | 核對全序列影像、來源宣告、空間幾何、使用過的參考標籤、保存遮罩與稽核鏈；不符時攔截 |
| 所選模型未完成也可核准 | 所選辨識或分割受阻時不可核准；允許填原因退回 |
| 歷史結果與目前病例狀態混淆 | 另列目前來源狀態，保存的歷史結果不改寫；有效歷史可匯出，不能帶入目前報告 |
| 分析 JSON 或歷史版本被修改未被發現 | 讀取與匯出核對保存時的 SHA256；不符時停止相關操作 |
| Windows 舊版文字檔使用 CRLF | 相容舊版已稽核內容的 CRLF/LF 換行；新寫入固定 LF。影像與遮罩仍按原始位元組核對 |
| 討論內容未保存就切換或覆核 | 顯示未保存提醒、停用覆核與退回；切換病例、歷史、重新執行或載入體模前確認捨棄 |
| 病例尚在載入便執行 | 載入期間鎖定操作；載入失敗恢復前一病例與結果 |
| 分割欄位拼錯卻執行預設閾值 | 拒絕未定義分析欄位，請求者不能指定操作帳號 |
| 啟動檢查與實際可執行條件不同 | 先核對 MRI 標籤與對齊影像；本機模型清單使用與執行相同的下載、用途及引擎規則 |

急性警訊仍優先處理；該分支跳過一般影像檢查並禁止核准一般分析。術前討論仍由人員記錄，只產生討論就緒狀態，不選定手術或開立醫囑。

## 操作

1. 完整解壓，Windows 11 安裝 Python 3.11 x64 與 Python Launcher，雙擊 start_demo_windows.cmd。
2. 首次建立自己的本機帳號；選 MRI 與「提供的研究標籤」，執行後查看原圖、遮罩、比對、3D與證據圖。
3. 修改術前討論後先保存；逐項核對完成與受阻項目，再開啟分析覆核、勾選確認。
4. 核准後可帶入原報告工作站。複製、儲存草稿及正式簽核仍各需操作。

更新既有安裝前停止服務並備份整個資料目錄。程式未更動 SQLite schema；保留原本資料目錄、帳號、影像與完整稽核資料，並保留現場自訂的 config.json、模型設定及權重。不要只搬移分析 JSON。
