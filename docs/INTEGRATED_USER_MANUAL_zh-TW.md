# CardioAgent 整合影像分析系統操作手冊

本手冊說明 CardioAgent v2 的安裝、影像檢視、整體分析、結果比對、影像與證據圖解釋、3D 表面重建、報告及術前討論。系統沿用既有本機工作站、工具執行器、模型驗證、人工覆核與稽核架構。操作者應先確認資料來源與分析模式，再依結果中的來源、單位及限制完成覆核。控制項「帶入報告準備」用來銜接既有報告流程；分析與報告各自保留覆核狀態。

本版提供可實際執行的流程及量測；真實心臟 CT 的辨識能力仍取決於另行登錄的已訓練模型。內附合成 CT 與 3D 體模用於軟體展示，ACDC MRI 用於研究閱片、影像量測，以及原始檔提供標籤的參考表面重建。實際分析紀錄和本版驗證資料是判斷完成狀態的依據。

## 一 安裝及啟動

Windows 使用者先安裝 Python 3.11 x64 及 Python Launcher，將完整套件解壓到可寫入的資料夾，再雙擊 `start_demo_windows.cmd`。首次啟動會利用隨附的 Windows wheelhouse 建立執行環境；此過程不下載 LLM、影像模型或 AMD 驅動。

```powershell
py -3.11 --version
.\start_demo_windows.cmd
```

若需手動安裝選用的影像推論依賴，使用 `setup_windows.ps1 -Offline -WithVision`。Linux 開發環境需安裝相容平台的套件；Windows wheels 不適用 Linux。

瀏覽器開啟 `http://127.0.0.1:8765`。首次自行建立本機管理者，密碼至少 12 字元；系統沒有預設密碼。後續使用相同資料目錄啟動會保留帳號、影像與操作紀錄。多次彩排請指定新的資料目錄，保留前次證據。

```powershell
.\.venv\Scripts\python.exe run_demo.py --data-dir integrated_rehearsal02 --port 8766 --open-browser
```

新版預設資料目錄為 `integrated_demo_data/`，與先前競賽版的 `demo_data/` 分開。服務只接受本機連線。備份前先停止工作站，再備份整個實際資料目錄；不要只複製服務執行中的 SQLite 主檔。

## 二 確認資料和模式

| 資料與模式 | 可執行內容 | 結果的適用範圍 |
|---|---|---|
| 合成 CT 與 demo | 幾何候選、完整工具流程、參考框比對 | 驗證流程及比對程式，不能當作臨床準確度 |
| 已登錄 CT 模型與 model | 已訓練 ONNX 候選定位、來源及模型雜湊 | 模型契約、前處理及資料類型須一致 |
| MRI 或匯入影像與 inspect | 品質、強度統計、閾值遮罩、可用的表面重建 | 研究量測；不套用 CT 鈣化模型 |
| MRI 原檔提供的研究標籤 | 由選定代碼建立遮罩與參考 3D 表面 | 未執行 AI 推論；類別對照及物理間距未驗證 |
| 3D 合成體模 | 已知間距的體積量測、獨立參考遮罩比對、OBJ 與 STL | 數學體模的軟體驗證，非病人解剖重建 |
| 完整幾何 DICOM 序列 | 檢查方向、序列一致性、切片排序與體素間距 | 幾何成立才可使用 mm 與 mm³ |
| 缺少空間資訊的 PNG 或 MRI | 切片及像素量測、以體素座標展示 | 不能將 voxel 或 px 換成病人尺度的 mm |

在工作站持續核對病歷代碼、檢查單號與影像來源。同一張圖上的候選框、參考框和閾值遮罩有不同來源，不能互相代替。合成背景欄位為虛構展示輸入。

## 三 整體分析流程

從工作站開啟 `/analysis` 整合分析工作區。左側選擇病例，或按「載入 3D 合成體模」新增已知幾何的獨立體模；再選適用模式。原始切片保留作為比對基準；閾值、中心切片、本機語言模型及比較紀錄會與分析一併保存。

1. 核對影像類型、切片數、來源與空間單位；先確認急性警訊狀態。
2. 模式選單中，「合成高亮區域 · 流程測試」對應 demo、「已登錄 CT 候選模型」對應 model、「僅量測與預覽 · 不辨識病灶」對應 inspect。未登錄模型時，model 模式會顯示受阻原因，不自動改成合成辨識。
3. 在「分割來源」選擇「強度閾值 · 非解剖分割」、「已登錄 ONNX 分割模型」，或有來源時的「提供的研究標籤 · 非 AI 推論」。閾值模式填入原始儲存強度的門檻；模型模式使用已登錄的前處理；當病例提供研究標籤時，於「研究標籤類別／比對範圍」選「類別 1＋2＋3 聯集」或單一提供類別。按「執行完整分析」，逐項檢視品質、候選、解釋、比對、3D 與討論資料。不同階段分別顯示完成、受阻或不適用。
4. 在「原圖與辨識」及「遮罩與比對」分頁比較原圖與結果疊圖，開啟候選或來源節點，核對索引、座標、引擎及參數。
5. 在「3D 重建」檢查座標及單位，旋轉、縮放模型後下載 OBJ 或 STL；保留分析 JSON 說明模型來源。
6. 在「證據圖解」追查來源連結，再到「處置與術前討論」補齊人工核對旗標，按「保存討論檢核」確認已知資料、缺漏及討論來源。
7. 選擇「人工覆核通過」或「退回分析」，並使用「下載完整分析」保存紀錄；如需正式報告，仍須回到報告工作區編輯、儲存及獨立簽核。

按「人工覆核通過」後，需在確認視窗勾選已核對本次病例、來源、影像、分割與比對範圍，再按「確認覆核」。分析核准只表示本機研究流程已覆核；它不會開立手術醫囑、院內排程或自動選擇治療方式。

## 四 影像辨識與結果疊圖

候選定位回傳的是切片上的像素框、信心值、模型或測試引擎、模型雜湊與執行耗時。合成候選的信心值不會偽裝成模型機率；零候選也不能解讀為已排除疾病。

實際 CT 模型須符合固定契約：512×512 像素、前中後三張切片組成 2.5D 輸入、float32 NCHW、像素值除以 255，並輸出尚未 NMS 的單類 YOLO 結果 `[1,5,N]`。本版對 DICOM HU 的顯示與訓練所用的 8-bit 模型輸入分開管理；未核對前處理時不直接推論。

閾值遮罩是依像素強度產生的可重現分割預覽。調整閾值會改變前景體素與表面；遮罩沒有自動冠以心肌、血管或病灶的臨床名稱。

分割也可選擇已登錄的 ONNX 模型。模型需明確指定 CT 或 MRI、固定輸入尺寸、前處理窗值、類別名稱與目標類別，且核對 SHA256；未登錄、尺寸不符或類型不符時會停止分割，不以閾值代替模型。此路徑使用逐切片的 float32 `[1,1,H,W]`，輸出 `[1,C,H,W]` logits 後選定目標類別；套件未附經訓練的解剖分割權重。模型類別名稱與訓練聲明仍須以獨立資料驗證。

原始 ACDC HDF5 檔案另提供與影像對齊的 `label` 資料組。選「提供的研究標籤 · 非 AI 推論」時，系統使用原檔標籤建立遮罩，不呼叫 AI 模型。「類別 1＋2＋3 聯集」會排除原檔背景代碼 0，代碼 1、2、3 也可分開重建；各類別在選單中保留「名稱未核實」標示。

目前來源沒有可核對的類別名稱、標註者與空間間距資訊，因此畫面保留「研究標籤代碼」名稱，不能自行命名為特定心室或心肌。使用同一份標籤建模時不再把它當作獨立真值自評 Dice；mm³ 仍留空，表面採 voxel 座標。本次只有 8 張切片，尚未驗證完整掃描覆蓋或心動週期資訊，不能據此估計心功能。此模式與 T=128 的強度預覽，以及已登錄模型推論，皆是不同來源。

## 五 AI 語言模型與圖解釋

本機 LLM 可整理已驗證的合成流程事實，文字摘要與原始量測分開保存。介面應能辨認本次採用規則、本機模型或規則接續，以及接續原因。模型不存在、尚未下載、用途不符、回應格式不符或企圖走雲端路由時，系統保留可查閱的原因。

場前先啟動 Lemonade，再用實際清單設定模型。下列指令不下載模型；請將 ID 換成服務回傳的已下載模型，並在設定後重啟工作站。

```powershell
.\.venv\Scripts\python.exe scripts\configure_lemonade.py --list
.\.venv\Scripts\python.exe scripts\configure_lemonade.py --model "實際文字模型ID"
.\.venv\Scripts\python.exe scripts\configure_lemonade.py --speech-model "實際語音模型ID"
```

報告準備中的人工逐字稿與六欄來源事實保持可覆核。語音服務只有實際回傳轉錄時才顯示逐字稿；未配置時可改用人工文字。LLM 摘要不會取代專用影像模型、簽核者或原始影像。

影像解釋會列出候選所在切片、像素座標、引擎、閾值與來源關係。證據圖顯示影像、模型、參數、結果、比較與覆核節點之間的連結，用來追查結果如何產生。這些說明不等同 Grad-CAM、注意力圖或神經模型的因果解釋；沒有實際執行的可解釋性方法就不顯示相應宣稱。

## 六 辨識結果比對

有獨立參考框時，系統以 IoU 及一對一配對計算 TP、FP、FN、precision 與 recall。資料不足時顯示無法評估，不以候選數代替準確度。

有與被評估方法分開提供的參考遮罩時，系統才計算 Dice；來源與臨床驗證程度會另行標示。內附 3D 體模的參考遮罩由幾何生成過程保存，與閾值分割結果分開。此結果僅反映該體模及指定參數，不代表真實影像分割效能。

比較既有分析紀錄時，應先核對病例、來源像素雜湊、切片索引及方法參數。相同影像上不同閾值的差異代表參數敏感度；不同分析的候選數或體積差異不能直接稱為病程變化。

## 七 3D 模型還原

3D 功能先把依序切片堆疊為體積，依選定來源取得前景遮罩，再擷取體素邊界表面。來源可為閾值、已登錄分割模型，或原檔提供的研究標籤；三者在紀錄中分開標示。網格為有上限的研究預覽，會顯示採樣步長及座標單位。畫面可旋轉及縮放；WebGL 不可用時採 CPU 線框預覽，無法據此證明 GPU 已完成驗收。表面較粗、邊界接觸影像範圍或幾何不完整時，不能用於切除界線、導引或手術器械定位。

DICOM 序列在幾何完整時依切片位置沿法向排序，檢查間距、方向及同序列一致性；缺漏或矛盾時，系統保留問題並改以 voxel 座標呈現。內附 ACDC MRI 沒有經此來源驗證的病人空間間距，因此不能輸出其物理體積為 mm³。

OBJ 可保留三角面及註解，STL 的通用格式本身不能可靠攜帶單位；匯入其他軟體時，必須依本系統的分析 JSON 核對座標與單位。下載檔案應與來源、閾值、體素間距及分析識別一起保存。

## 八 處置及術前討論

術前討論以人工核對的臨床資料與可回查來源建立清單。系統詢問急性警訊、冠狀動脈解剖、缺血評估、左心室功能、風險及共病、藥物與患者偏好等資料的完成狀態，不從候選框、MRI 強度或閾值網格推斷這些資訊。

有急性警訊時顯示優先處理；資料不完整時列出缺漏；資料已勾選完成時也只表示可供 Heart Team 討論。藥物治療、PCI 與 CABG 的一般選項說明提供討論背景，不作個別病人的排序或自動手術適應症判定。來源採 2021 ACC/AHA/SCAI 冠狀動脈血運重建指引、2024 ESC 慢性冠心症指引，並以 AHA 2025 高齡者科學聲明補充衰弱及偏好議題；實際院內決策仍需核對適用版本與臨床情境。

操作者可保存醫師的討論文字，並將其標為人工提供。模型摘要、幾何體模與人工建議分別保留來源，避免在匯出報告中混淆。

## 九 報告及覆核

v2.0.1：術前討論的檢核或備註變更後，請先按保存。未保存時覆核按鈕停用，切換病例、載入歷史或重新執行會詢問是否捨棄；取消會保留編輯。病例載入期間無法執行分析，載入失敗會保留原病例及結果。

分析覆核須開啟確認視窗，勾選本次病例、來源、影像、分割與比對範圍；伺服器也會檢查此確認及版本。影像、幾何、使用過的標籤、遮罩或分析紀錄不符時，不能核准或帶入報告。所選辨識／分割未完成時，也需修正後重跑。退回分析仍須填寫原因。

來源已變更的歷史分析可匯出保存的事實，匯出另附目前來源檢查狀態；畫面也會列出攔截原因。這不會修改原本的歷史覆核狀態。分析或歷史版本的內容雜湊異常時會停止讀取或匯出，請恢復完整備份或重新分析。

影像工作站保留六欄報告：適應症、技術、比較、所見、結論、限制。將準備內容帶入編輯區後，先人工核對再儲存草稿；送交初步報告後，由影像覆核角色確認病例與內容並簽核。簽核後原報告鎖定，更正以補充報告保存。

分析覆核、協作任務核准及報告簽核為不同操作，各自記錄操作者與版本。分析核准不代表報告已簽核，也不表示已取得臨床或手術批准。匯出 FHIR JSON 僅建立本機檔案，沒有寫回 HIS 或 PACS。

## 十 操作問題與結果判讀

| 畫面或結果 | 應採取的操作 |
|---|---|
| CT 模型未登錄 | 使用已揭露的合成流程彩排，或完成權重與前處理登錄後重跑 model |
| 本機模型不可用 | 檢查 Lemonade、模型 ID、用途、下載狀態及允許的本機後端 |
| MRI 不適用 CT 模型 | 切換 inspect，保留 MRI 閱片與量測，另準備適用模型 |
| 物理體積為空值 | 缺少可驗證間距或幾何；保留體素數，不填入推估 mm³ |
| 無參考框或遮罩 | 僅回報可觀察結果，不填入 precision、recall 或 Dice |
| 3D 前景為零或網格受阻 | 核對強度範圍及閾值，檢查影像是否過小或無有效體積 |
| 分析或報告版本衝突 | 重新載入，檢查他人或其他視窗的變更後再操作 |
| 已簽核內容不能覆寫 | 使用補充報告，保留原始簽核與更正理由 |

現場驗收需保存日期、硬體、記憶體、OS、驅動、模型、後端、首次與暖機耗時、尖峰記憶體，以及成功、受阻及接續原因。軟體測試通過、CPU 執行成功或列出 NPU 裝置，都不能單獨證明已在 AMD NPU 執行或完成臨床效能驗證。

## 十三 參考來源及模型登錄

術前討論的來源摘要和版本保存在 `assets/sop/clinical_sources.json`，畫面可開啟對應官方來源。主要依據為 2021 ACC/AHA/SCAI 血運重建指引、2024 ESC 慢性冠狀動脈症候群指引及 AHA 2025 高齡者血運重建科學聲明；科學聲明不替代臨床實務指引。

DICOM 空間欄位依 DICOM PS3.3 Image Plane Module 解讀。PixelSpacing、ImagePositionPatient 及 ImageOrientationPatient 必須共同核對，不能用 SliceThickness 或檔名單獨替代切片間距。

模型接入的方法、IoU／Dice 定義、空間座標及證據圖說明見 `docs/PIPELINE_METHODS.md`；分割登錄工具為 `scripts/register_segmentation.py`。請先執行該工具的 `--help`，依原模型的實際訓練及匯出契約提供參數，不沿用示範值。
